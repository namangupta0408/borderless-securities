1. Start the chain and deploy contracts

Run these once, from the project root, before using this UI. See README.md for full detail.

# Terminal 1
npx hardhat node

# Terminal 2 (after node is running)
npm run deploy

# Terminal 3
cd backend && npm install && npm start

Demo wallet directory

For this prototype, 10 well-known local test wallets stand in for real members (Owner A, Member B, C, D...). In production these would be the members' own wallets (MetaMask / WalletConnect), never keys held by the backend.

Register a member

Assigns a unique member code (MEM-0001, MEM-0002, ...) and marks the wallet KYC-eligible.

Freeze / unfreeze a member

A frozen wallet is instantly blocked from sending or receiving tokens — enforced by the smart contract, not policy.

Onboard a company

Registers the company and its owner. Voting rights default to this owner and stay there until a full redemption.

Verify Pillars 1 & 2 (KYB + Owner KYC)

Both must pass before a lien token can ever be issued for this company.

Company status

Issue a lien token

Deploys a brand-new, isolated token contract for this company's lien and mints the full fixed supply directly to the owner. Every company gets its own token — never pooled.

Token info

Transfer tokens (A → B → C → D...)

Only KYC-eligible, non-frozen wallets can send or receive. Voting rights are untouched by transfers — they stay with the original owner.

Check balance

Request redemption

Current holder burns their tokens to formally request the real, previously-liened shares be released to them.

Compliance: execute redemption

Confirms the real-world share transfer has happened. This is the on-chain audit trail entry.

Move voting rights

The final, deliberate step: voting rights only move when compliance confirms it — not automatically.
